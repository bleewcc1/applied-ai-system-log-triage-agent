# Snort Network Intrusion — Incident Response Playbook

Standard response steps for alerts generated by Snort (or similar
network-intrusion detection). Steps are grouped by severity so the triage
agent can retrieve only the section matching the alert it is handling.

## Severity: CRITICAL

1. Isolate the source and destination hosts from the network immediately
   (disable switch port or apply a host-level block).
2. Block the offending IP address(es) at the perimeter firewall.
3. Preserve a packet capture and the Snort alert log for forensic review —
   do not rotate or delete logs covering the incident window.
4. Escalate to the on-call security lead within 15 minutes.
5. Begin a timeline of lateral-movement indicators (auth logs, new
   processes, outbound connections) on the affected host.

## Severity: HIGH

1. Rate-limit or temporarily block the offending IP address(es) at the
   firewall pending investigation.
2. Pull the full session/connection logs for the source and destination
   hosts covering the alert window.
3. Check the destination host for signs of compromise (unexpected
   processes, new accounts, modified binaries).
4. Notify the security team within one hour.

## Severity: MEDIUM

1. Add the source IP address to a watch list for continued monitoring.
2. Review recent alerts from the same source IP for a pattern (repeated
   scanning, credential-stuffing attempts).
3. Confirm the targeted service is patched and not exposed unnecessarily.
4. Log the finding in the daily security report.

## Severity: LOW / UNKNOWN

1. Log the alert for trend analysis; no immediate blocking action required.
2. Re-evaluate if the same source IP generates additional alerts within
   24 hours.
3. Periodically review low-severity alerts in aggregate for emerging
   patterns.

## General Notes

- Never block an internal management or monitoring IP without
  confirming it is not a false positive.
- All blocking actions must be logged with timestamp, analyst, and
  justification.
